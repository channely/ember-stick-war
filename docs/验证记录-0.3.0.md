# 0.3.0 验证记录

## 验证范围

本轮将规则验证、真实输入验证和人工画面检查分开记录，避免用“页面能打开”代替完整玩法验收。

- Node 规则测试：资源往返、训练队列与人口、六兵种动作、命中、存档、成长、关卡目标。
- 连续战役：使用新存档的实际资源完成新主线，不依赖道具和皮肤。结果由战役测试输出。
- 浏览器交互：真实鼠标、键盘与 Chrome DevTools Protocol 多点触控；不向游戏安装调试后门。
- 界面尺寸：1440×900 桌面、844×390 手机横屏、390×844 手机竖屏、1024×768 平板。
- 教学材料：原 12 课、新增实验、代码编辑预览、学习记录、下载材料。

## 浏览器场景说明

`scripts/browser-qa.mjs` 为独立交互测试构建合法的 `Battle` 快照，例如预置指定兵种及皮肤的练习场。快照仅确定起点，随后均由真实输入操作。它不构造通关结果，不作为连续战役通关证明。

测试通过既有 `pagehide` 保存机制读取快照，用于比较移动、资源、库存、队列与动作结果。存档恢复本身另有真实刷新测试。

验收覆盖：采矿与征兵入口、三个整军命令、法术库存与冷却、队列取消、单兵二维移动、格挡、跳斩、弓瞄准发射、矛投掷、召唤、巨人地震条件、六兵种练习入口、暂停/失焦/旋转后的输入释放、四尺寸一屏操控、全屏菜单、亲子暂停下令、旧档迁移不重复退款、兵器升级与宝石货币隔离、按兵种购买装备。

浏览器报告和截图生成到 `artifacts/browser-v03/`，该目录不纳入源代码版本控制。

固定步长测试在 30/60/120 Hz 下回放真实手操与军团命令，包含接管、移动、短按跳斩、反向纵深移动、交还指挥、驻营和进攻，结果一致。

战役路线采用盾弓法师协同和剑士早压两种配置；随机种子为 24、193、7921。每条路线从新存档连续推进，只使用公开招募、军团命令及通关所得升级点。没有消费背包道具、没有更换经典皮肤、没有注入额外黄金或伪造关卡解锁。每秒检查双方金币账本与 50 人口约束。此结果证明这些策略可完成全程，不等于所有难度、所有阵容已经平衡。

浏览器验收在通关模拟之外验证了以下实际结果：

- 手控矿工通过 WASD 走到矿旁、按住空格采金，再走回营地完成交付；练习不会奖励战役宝石。
- 敌人在身后时，手控剑士不自动转身，朝前挥击不会伤到身后敌人；玩家向左移动明确转身后可以命中。
- 快速按放 Q 可以召唤法师随从、施放装备巨人的地震；E 投矛后角色失去长矛。
- 触屏弓手按住动作按钮、小幅拖动再松开，箭矢使木桩实际扣血；明显偏转瞄准后仍发出箭，但木桩不扣血。
- 横屏手机、竖屏手机和平板中，双指同时操作摇杆与攻击，能观察到真实位移和攻击；旋转、取消触控后不持续移动。
- 进入练习前的战役快照得到保留；练习期间刷新后仍可返回原战局，黄金、时间、指令和队列一致，原战局恢复为暂停。营地换装不移除巨人练习借用的装备。
- 旧档原文保留，新战役从第一关开始；旧皮肤和成本退款迁移仅执行一次。

### 人工画面检查

检查了桌面初始战场、手机横竖屏、巨人地震、弓手瞄准、营地、战役地图及亲子工坊截图。修复了桌面征兵卡文字被裁切的问题；四种验收尺寸中的战场、征兵、军团命令和手操区均可在一屏内使用，未出现横向溢出。角色装备、准星、选择轮廓和动作反馈可辨认。

### 复现命令

```sh
npm test
npm run check
npm start
# 另一个终端，在静态站点可用后：
npm run test:browser
node scripts/workshop-qa.mjs
```

浏览器脚本支持 `BASE_URL`、`PLAYWRIGHT_MODULE`、`CHROMIUM_PATH` 与 `QA_ARTIFACTS`。调试单一场景可用 `QA_FILTER` 正则筛选；最终完整验收不设置筛选。截图与报告属于验证产物，不纳入源码提交。

### 验证边界

测试使用 Chromium 实际输入和四种屏幕尺寸，未声称覆盖全部实体手机或 Safari。规则对齐来源与网页标定参数见《规则对齐-0.3.0》；通过测试并不代表获得原作未公开数值或逐像素复刻。
